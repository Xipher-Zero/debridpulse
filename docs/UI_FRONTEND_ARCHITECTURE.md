# DebridPulse Frontend Architecture

This document describes the live post-audit frontend ownership model. It records current owners and boot relationships; it does not describe historical correction layers as though they were still canonical.

The application reports `1.0.14` for the current development tree; `1.0.13` is the latest published release.

## Core rule

Every visible behavior has one bounded structural/render owner and intentionally composed styling. Broad post-render correction runtimes, correction-named stylesheets, and compatibility globals that replace unrelated page owners are prohibited. No owner reassigns another owner's global function to graft behavior onto it (no monkeypatch/wrapper substitution) — accepted behavior is implemented directly by the real owner, or reached through an event the owner already dispatches.

`frontend/static/index.html` owns the static shell and the six reachable navigation surfaces: Dashboard, Downloads, Activity Log, Statistics, Settings, and Help & License. The retired `view-changelog`, `view-aria2queue`, and `view-support` surfaces are absent from the shell.

## Boot graph

`index.html` parser-loads the application and every bounded presentation owner as direct, explicit `<script defer>` dependencies, in the order the owners actually need. Required production dependencies are never dynamically injected: a load failure is a visible page error, not a silently-continuing "ready" application. Provider Status (`ui-provider-status.js`) no longer bootstraps other modules — it owns provider-status candidate discovery, observation, invalidation, and rendering only.

`ui-presentation-loader.js` is physically absent. It is a retired presentation-loader dependency and must not return under another correction-layer role.

The bounded presentation owners, in their required load order (each depends only on `app.js` and the owners before it in this list), are:

- `ui-toast-contract.js` — public toast copy/timing bridge to the canonical `operator-title.js` presenter.
- `ui-processing-presentation.js` — pause-banner/shim visibility (static markup in `index.html`), `configuredMaxConcurrency()` (the one read of scheduler capacity, `transfer_policy.max_concurrent_executions`), and the canonical pause-eligible presentation-status set (`PAUSEABLE_PRESENTATION`). It creates, removes, or relabels no other owner's markup.
- `ui-transfer-source-presentation.js` — the neutral host/source-icon mapping and markup owner, shared by every surface that renders a transfer row.
- `ui-file-selection.js` — the universal file-selection modal, browser-local draft state, and list chip; must load before the two owners below because they call `window.DPFileSelection.chipMarkup()` while building row markup.
- `ui-dashboard-transfer-presentation.js` — Dashboard Recent Activity row presentation. Consumes `window.DPTransferSourcePresentation` for source icons; does not define its own host mapping.
- `ui-section-nav.js` (`window.DPSectionNav`, with `ui-section-nav.css`) — the one section navigator of a master-card header, shared by Settings and Help: from 780px it measures the page's rendered tabs and identity copy and shows either the complete strip or the compact navigator (First, a bounded window onto the same tabs, Last), places and fades that window and slides it through `DPMotion` only when the page's own choice moves it. It renders nothing and keeps no selection: each page owns its header markup, tabs, ARIA, events, panels and choice (`chooseTab`), and creates its navigator with `DPSectionNav.create({nav, copy})`.
- `ui-search.js` — the one search lifecycle (`window.DPSearch`) of Downloads and the Activity Log: each list's search box, its 250 ms commit, every list request's identity (stale answers are discarded), and the query the shown results answer, without adding any element or geometry of its own (a rejected query or an ID-only answer is one toast). It never interprets the text; the backend's one search language (`backend/core/search_contract.py`) does, and reports what it searched and how complete the answer is.
- `ui-downloads.js` — the sole Downloads controller/renderer owner: list page state, the bounded `/torrents` fetch, final row rendering, filtering, pagination, date mode/menu, measured capacity/page sizing, list selection state, bulk actions, and refresh; its search runs through `DPSearch`.
- `ui-activity-log-runtime.js` — the sole Activity Log behavior and render owner: it binds the static filter controls in `index.html` once, owns server-side severity/timeframe/Event Type filtering (the one applied combination, its Filter Results panel and Clear Filters), timestamps, and row rendering, and exposes only `window.DPActivityLog`; its search runs through `DPSearch`.
- `ui-settings-archive-passwords.js` — Automatic Extraction archive-password editor interaction.

There is no `DPUICorrectionBatch1`, `DPUICorrectionBatch1Final`, or `DPUICorrectionP4Repair` runtime contract in the boot graph.

`ui-group-candidates.js` (`window.DPGroupCandidates`) is parser-loaded as an ordered `defer` script alongside `ui-detail-candidates.js` — it is not in the bounded-owner list above because it must be ready for the first Downloads / Recent list render. It is the single owner of transfer-level **common-source group switching**, and keeps two facts strictly independent: **membership** — which source hosts exist as a canonical candidate on every current authoritative file of a transfer (`commonHosts`, independent of `switch_eligible`/artifact state/selection) — and **actionability** — which of those common hosts the group can currently converge to (`actionableHosts`). Membership drives the launcher count/visibility; actionability drives only whether a common host's row offers "Switch to this source". It also owns the shared chooser popover and switch orchestration over the existing exact per-file candidate endpoint, and owns no switching engine, candidate model, routing, recovery, provenance, or lifecycle. Downloads, Dashboard Recent Items, and the Details Files-section header all invoke the same `DPGroupCandidates.launcherMarkup()` / `DPGroupCandidates.open()`; none carries its own group semantics. The per-file candidate disclosure (`ui-detail-candidates.js`) and the individual rows are a separate owner and are untouched by it.

## Downloads ownership (CANON-001 closure)

`ui-downloads.js` is the **sole** Downloads controller/renderer owner. `app.js` retains only true application-shell/shared responsibilities that Downloads also consumes — `api`, `esc`, `toast`, `fmtSize`, `parseApiDate`, `badge`, `progress`, `providerChip`, `transferDisplayStatus`, `setButtonPending`, the shared modal (`DPModal`/`showDetail`/`closeModal`), and the shared row-interaction guard `dpIsInteractiveRowTarget` — because Dashboard Recent also calls every one of them. `pauseT`/`resumeT` stay in `app.js` for the same reason (both Dashboard Recent and Downloads call them); `deleteT`/`retryT` are Downloads-only and live in `ui-downloads.js`.

There is exactly one Downloads render pass. `ui-downloads.js` never replaces `api`, `loadTorrents`, or `renderTorrentPagination` on another owner, and never re-renders an inherited Downloads implementation and repairs its DOM afterward — the presentation-status-driven badge/progress/action-button state, the source-icon/file-selection/candidate-launcher slot, and the Downloads-local date format are all computed inline while building each row, the same way Dashboard Recent already computes them.

`badge()` and `transferDisplayStatus()` (in `app.js`) natively consume the backend-projected `presentation_status`/`presentation_label`/`presentation_badge_status` fields (`transfers.presentation_repository.effective_presentation`) when present — this used to be grafted on at runtime by `ui-processing-presentation.js` reassigning both globals; it is now part of their one canonical definition.

## CSS composition

`style.css` is the canonical import graph — the single top-level application stylesheet, and a pure `@import` list (it carries no literal rules of its own, since `@import` must precede all other rules). It is a straight `@import`-per-component/page list (folded in from the retired `style-v11.css`, which contained only that import list). Correction-named Batch-1 styles are absent. Accepted geometry is assigned to explicit component owners: provider summary, Dashboard transfer presentation, Downloads (`ui-downloads-page.css`, which also carries the pause shim, date menu, and name metadata material folded in from the retired `ui-downloads-presentation.css` and `ui-downloads-desktop.css`), Activity Log controls, archive-password editor, and Details file-status geometry.

The historical base/reset layer that used to live in `style.css` itself (pre-v11) has no file of its own any more. `ui-legacy-foundation.css` briefly held it as an interim `@import`-first file so `style.css` could become a pure import list; that intermediate file was itself retired once every rule in it was given a real per-responsibility owner: global reset and `html`/`body` base geometry moved to `ui-foundation.css`; the light/dark legacy custom-property aliases (`--bg`, `--text`, `--border`, …) merged into `design-tokens.css`'s own `:root`/`body.light` blocks alongside its `--dp-*` tokens; sidebar/topbar/nav chrome moved to `ui-shell.css`; the `.aria2-cap-*` speed-cap popover moved to `ui-dropdown-contract.css`; Dashboard-only material (hero stats, KPI strip, drag-reorder, quick-add) moved to `ui-dashboard.css`; Statistics-only material moved to `ui-statistics-page.css`; Settings-only material moved to `ui-settings-page.css`/`ui-settings-form-layout.css`; Help-only material moved to `ui-help-page.css`; Activity Log material moved to `ui-activity-log-page.css`/`ui-activity-log-controls.css`; the modal/toast shells moved to `ui-modal-contract.css`/`ui-toast-contract.css`; cross-cutting, non-page-specific residue (`.kv-list`/`.kv-row`, the `.card-title`/`.scard-body` layout-only residual the material layer intentionally leaves to a shared owner) moved to `ui-shared-contract.css`; and generic component material (`.card`, `.btn`, `.input`, `.badge-*`, base `table`) moved to `ui-universal-language.css`, which already carried the `:is(.dp-*, <legacy class>)` bridge selectors that made most of that material provably dead on the spot. A body of confirmed-orphaned markup (an old About/changelog panel family, pre-clean-room Settings classes) was deleted outright rather than relocated. `ui-legacy-foundation.css` no longer exists, is not imported anywhere, and `test_no_future_legacy_dumping_ground_stylesheet` (`test_v112_canonical_flattening.py`) guards against a similar single-file catch-all reappearing.

`ui-detail-candidates.css` is the single bounded owner of candidate disclosure/panel styling and is loaded through the `style.css` `@import` graph (not runtime-injected). The multi-source candidate chip has one shared visual contract: `.dp-candidate-chip` material and geometry live in `ui-transfer-contract.css` (which already owns the reusable transfer/provider row contract); surface files add only bounded layout differences — Details interactive hover/focus in `ui-detail-candidates.css`; the Downloads and Recent Activity Name metadata rows use the shared geometry unchanged. The Details per-file disclosure and the transfer-level group launcher (`DPGroupCandidates.launcherMarkup()`, reused verbatim by Downloads and Dashboard Recent Items) are both interactive `<button>` elements sharing that chip family; the group launcher's interactive treatment and the chooser popover rows — including the muted no-action row style for a common host that is not currently actionable — live in `ui-group-candidates.css` (imported once through the `style.css` graph), never a second base definition of `.dp-candidate-chip`. The chooser reuses the canonical body-level `.dp-dropdown-menu` shell. The Lucide `network` glyph geometry has exactly one owner, the `LUCIDE` set in `operator-title.js`, rendered through `window.DPIcons.svg('network', …)`.

`body.dp-v11-structural` is gone. It was a specificity-boosting scoping class applied unconditionally to `<body>` so a scoped component rule would always beat an unscoped legacy rule regardless of import order; `git grep -n 'dp-v11-structural' -- frontend/static` returns nothing, `<body>` carries no class, and every previously-scoped selector across the ~40 files that used it now stands on its own, unscoped, relying on the canonical import order (legacy content, if any, first; component/page owners after) rather than an inflated specificity to win real cascade ties. The one selector where removing the scoping class actually changed which of two competing files won a shared property — `.aria2-cap-menu`'s `border-color`/`box-shadow`, contested between `ui-shell.css` and `ui-dropdown-contract.css` — was resolved by deleting the losing (superseded) declarations from `ui-shell.css` rather than re-introducing a specificity trick; `ui-dropdown-contract.css` is now the sole, unscoped owner of that popover's surface material. Every other de-scoped selector was verified, file by file, to still resolve to the exact same winning property value it did before removal (source: this pass's own before/after cascade-winner diff over every rule in the import graph).

## Single-owner invariants (DP 1.0.12 final audit)

These are enforced by static tests (`backend/tests/test_ui_runtime_architecture_contract.py`) and by Browser Runtime specs.

- `app.js` is the one Server-Sent Events connection owner. It creates the only `EventSource` (for `/api/events/stream`) and registers `duplicate_consolidated` directly; the handler asks `window.DPIcons.consolidationToastCopy(...)` for the copy and shows it with `window.DPIcons.toast(...)`. The native `window.EventSource` is never replaced or wrapped.
- `operator-title.js` owns toast/icon presentation and the consolidation toast copy only. It does not create, wrap, proxy, or replace any EventSource.
- Activity Log behavior is owned only by `ui-activity-log-runtime.js`. `app.js` holds no Activity Log implementation (no `_allEvents`, `loadEvents`, or `filterEvents`), and no Activity Log compatibility globals (`window.loadEvents`, `window.filterEvents`) exist.
- Topbar concurrency is rendered by `app.js`'s `updateAria2TopbarBadge`. Its denominator is `settingsData.transfer_policy.max_concurrent_executions` and nothing else: a stale or native aria2 value can never replace scheduler capacity. There is no wrapper runtime: `ui-topbar-concurrency.js` is retired and absent.
- No owner reassigns another owner's global or a native browser API. An owner may publish its own exported namespace and may listen to explicit events another owner emits.
- The browser session owner (`auth.js`) publishes its authenticated request path as `window.debridPulseAuth.fetch`; every application HTTP call uses it. The native `window.fetch` is not replaced.
- Settings markup has one owner. `ui-settings-page.js` renders every tab, panel, card, icon and ARIA attribute exactly once; no other script rewrites, reparents, decorates or repairs it after it renders. Bounded feature owners (`ui-settings-directory-picker.js`, `ui-settings-executor-work.js`, `ui-settings-archive-passwords.js`) add behavior for their own feature, and only through their own mount, on the explicit `debridpulse:settings-rendered` event. `ui-settings-backup-manager.js` and `ui-settings-help.js` mount nothing into Settings: the page opens them, and they render only inside their own dialog. The accessibility runtime no longer projects tab semantics onto Settings.
- The application dialog shell has one owner, `ui-settings-modal.js` (`window.DPSettingsModal`, a direct `<script>` in `index.html` that loads before every consumer). It owns mount/unmount, overlay, shell, ARIA base wiring, the focus trap, Escape, initial focus, exactly-once settlement, focus restoration and the body scroll lock; its neutral `.dp-modal-*` contract lives in `ui-modal-contract.css`. Settings confirmations, the Settings directory browser and the Downloads removal confirmation are direct clients: they hand it content through `open({mount})` or `confirm(...)` and never query, wrap or rewrite the shell DOM. Focus is restored to the initiating control, else its equivalent replacement, else the nearest surviving region; a client whose accepted operation removes the initiating control names its own successor after its own re-render. Work the operator cannot stop is shown through the shell's own `progress(...)` shape (a restore in progress): a centred status with no header, footer or control, inert to Escape and the backdrop, closed only by its client.
- The shell provides stable mounts and the session owner populates its own: `index.html` contains `#sidebar-bottom-stack` and `#sidebar-auth-mount`; `auth.js` fills that mount and sets a state attribute on the stack. It does not move `.sidebar-footer` or any other owner's element.
- Global processing pause is operational state, not a setting. The backend's durable application state is its only authority; `AppSettings` has no `paused` field, nothing is written back into configuration, and the frontend keeps only a non-persisted `processingPaused` projection assigned from `GET /stats` and the pause/resume results (`settingsData` never carries it).
- Canonical settings fields are consumed directly: aria2 configuration from `settingsData.integrations.aria2.options`, AllDebrid credentials from `integrations.alldebrid.options`, execution policy from `transfer_policy`, the bandwidth cap from `execution_runtime_limits`. No flat alias (`aria2_*`, `max_concurrent_downloads`, `alldebrid_api_key`, ...) is read, mirrored, or written, and the whole-settings write never carries a canonical namespace or the read-only compatibility fields the server names in `compatibility_fields`.

## Accessibility and cross-cutting runtime

`ui-accessibility-runtime.js` remains a deliberately narrow cross-cutting module for ARIA, keyboard behavior, and universal select/dropdown projection across dynamically rendered controls. Its `MutationObserver` is not a general presentation-repair mechanism.

`operator-title.js` owns canonical icon/toast geometry and is not a runtime loader or DOM-repair layer.

`ui-tooltip.js` presents every application-owned informational tooltip; no owner writes a native `title` tooltip (document titles are not tooltips, and native file pickers and other browser or platform surfaces stay the browser's). It reads only `data-tooltip`, rewrites nothing an owner rendered, and touches the described element only to add, while shown, `aria-describedby` to its one tooltip element; the element's accessible name stays its own (`aria-label` or text).

`ui-settings-archive-passwords.js` fills the archive-password editor rows that `ui-settings-page.js` rendered (label, form-field textarea, editor container, reveal button and hint are all page markup) when the page announces `debridpulse:settings-rendered`; it observes no DOM, creates no scaffold, and hides or rewrites nothing the page rendered.

## Permanent qualification

Permanent CI uses Browser Runtime as the real-browser smoke contract for all six canonical navigation surfaces. Static architecture tests additionally prove correction-named runtime/style assets and legacy correction globals are absent; bounded owners contain their declared behavior and do not reclaim unrelated surfaces; the canonical CSS graph references only current owners; and the retired presentation-loader/finalization dependencies remain absent.

`ui-runtime.js` and `ui-downloads-runtime.js` are physically absent and must not be reintroduced as a corrective mechanism, and neither is the retired `ui-downloads-presentation.js`.

Browser Runtime validates load, six-surface navigation/reload, theme behavior, auth/error presentation, Dashboard/Downloads/Activity/Settings contracts, and absence of requests for retired correction assets.

## Change rule

New frontend work modifies the canonical owner or introduces a genuinely scoped owner. It must not add a new correction stylesheet generation, broad post-render patch script, presentation-loader/finalization dependency, monkeypatch of another owner's global, or compatibility global whose purpose is to undo another current owner.
